# Production

Production runs on one EC2 instance in a private subnet. Students reach it only through CloudFront over HTTPS. Student
data is stored as described in [AWS_STORAGE_SETUP.md](AWS_STORAGE_SETUP.md), in its own production copy.

```
browser ──HTTPS──▶ CloudFront ──VPC origin (AWS network)──▶ EC2 (private, no public IP), port 8080
                   security headers, HTTP→HTTPS                  │ codeai service (webapi.server --dev)
                                                                 │   ├─ S3 student data, as the prod app role
                                                                 │   └─ Bedrock (models, guardrail)
                                                                 │ codeai-sandbox user runs student code: no network
                                                                 ▼
                                                     NAT gateway ─▶ Bedrock, STS, SSM, Secrets Manager
```

| Stack | Template | What |
|---|---|---|
| `codeai-storage-prod` | [curriculum-and-progress.yaml](../infrastructure/curriculum-and-progress.yaml) with `Suffix=-prod` | Curriculum and student-data buckets, KMS key, the app role `CodeAITeam8App-prod-us-west-2` (only the server role can assume it) |
| `codeai-prod` | [production.yaml](../infrastructure/production.yaml) | VPC, NAT, the instance and its role, CloudFront, release bucket, teacher token (Secrets Manager), auto-recover and auto-reboot alarms |

## Deploy

From the repo root, with the venv Python and the account's admin credentials:

```sh
~/.venvs/codeai/bin/python -m deploy.production infra     # stacks + config/aws_storage.prod.json (commit it)
~/.venvs/codeai/bin/python -m deploy.production release   # build the current commit, install it, smoke-test
~/.venvs/codeai/bin/python -m deploy.production status    # URL, instance, release, health
```

A release is a commit. The tool refuses a working tree with uncommitted changes. It builds the student UI and packs only
what the server needs into `releases/<time>-<commit>.tar.gz` in the release bucket. It records that key in the SSM
parameter `/codeai-team8/prod/release` and runs [install.sh](../deploy/production/install.sh) on the instance through
SSM Run Command. Then it calls `/api/health` through CloudFront and checks that dev mode is off and storage is S3. The
instance keeps the last three releases. To roll back, set the parameter to an older key and run the same install
command, or release an older commit.

There is no SSH. Get a shell with `aws ssm start-session --target <instance id>`. Logs are in
`journalctl -u codeai`.

## What protects students on the instance

- **No way in except CloudFront.** The instance has no public IP. Its security group accepts port 8080 only from
  inside the VPC, where the CloudFront VPC origin connects. CloudFront redirects HTTP to HTTPS and adds the managed
  security headers (HSTS, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`).
- **Student code runs as `codeai-sandbox`** through `sudo` and [run-student-code](../deploy/production/run-student-code).
  - The grader ([engine/grader.py](../engine/grader.py)) copies the submission, checks, reference solution and
    database into a temp folder. Student code never needs `/var/lib/codeai`, and the sandbox user can't read it
    (0700).
  - The environment is cleared, so it gets no credentials, tokens or settings.
  - An nftables rule drops every packet the sandbox user sends. That blocks the internet, the instance-metadata
    credentials and the server itself.
  - Limits per run: 15 s of CPU, 1 GiB of memory, 64 processes, 10 MiB files.
- **Data on the instance** is in `/var/lib/codeai` (0700, owner `codeai`) on an encrypted EBS volume. Every change is
  copied to the production student-data bucket, and a new instance restores from it.
- **The teacher token** is generated by Secrets Manager (`codeai-team8/prod/teacher-token`). It's written to
  `/etc/codeai/env` (root:codeai, 0640) on each install. Teachers send it as the `X-Teacher-Token` header. Read it
  with `aws secretsmanager get-secret-value --secret-id codeai-team8/prod/teacher-token --query SecretString --output text`.
  To rotate it, change the secret, then run `release` again.
- **The AI inspector is on, for teachers only.** The service runs with `--dev`, so the corner button appears. Because
  the teacher token is set, the inspector's endpoints (`/api/dev/*`) answer only with the `X-Teacher-Token` header, and
  the panel asks for the token before showing anything. The calls include students' code and what they typed. They are
  kept in memory only (the last 300) and are gone after a restart. `release` fails its check if the inspector is ever
  on without the lock.
- **IMDSv2 only**, with a hop limit of 1.

## Limits

- **One instance, one Availability Zone.** If the host fails, the recover alarm moves the instance to new hardware.
  If the OS hangs, the reboot alarm restarts it. Expect minutes of downtime, not seconds. If the instance is lost,
  a replacement restores from S3 on its first start.
- **Student code can still read the reference solution and the checks** for the problem it is being graded on. It
  runs in the same process as the checks. That's a way to cheat, not a privacy risk.
- **No WAF and no rate limiting.** A flood of requests or code runs would slow the one instance. Add AWS WAF on the
  distribution (about $5/month plus requests) if the URL is shared widely.
- **Student pages trust the student id.** Anyone with a student's id can open their lesson. Ids are 128-bit random
  values and never appear in URLs that are shared.

## Cost (us-west-2, on demand)

About $50 a month, most of it the NAT gateway:

| Item | Monthly |
|---|---|
| NAT gateway | about $33 |
| t3.small | about $15 |
| EBS, KMS, Secrets Manager, alarms, public IP | about $7 |
| CloudFront, S3, NAT data | cents at class scale |
| Bedrock | per use |

`aws cloudformation delete-stack --stack-name codeai-prod` removes the app. The storage stack's buckets and key are
kept on purpose (`DeletionPolicy: Retain`).
